# Rule -> tier table

Generated by `tools/export_rule_tiers.py` from `hallucination_pipeline/policy.py`. Do not edit by hand.
Rules version 1.0.0 (patterns SHA-256 `1d10799fee96...`); policy version 1.2.0 (SHA-256 `f83ccde8857c...`).

Tier 1 = unsupported specifics; Tier 2 = external knowledge (D3). **strict** counts Tier 1 + 2, **lenient** counts Tier 1 only. Layers are listed in the order the sentence engine checks them. Every matched rule is kept (D18); the primary one is the first Tier 1 hit in this order, else the first counted hit. Soft certainty never decides on its own: it sends the item to the LLM judge. At explanation level, layers 1-3 are the old Phase 2 rules (C0, C2); layers 4-6 are added for C1 and C3 (at sentence level they always run). Layers 5 and 6 live in `policy.py`; the rule patterns are frozen. Every hit carries `hedged` (D17, lexicon below), which never changes its tier.

## Hedging lexicon (D17, frozen)

`could`, `may`, `might`, `possibly`, `potentially`, `perhaps`, `appear`, `appears`, `seem`, `seems`, `suggest`, `suggests`, `suggesting`, `consistent with`, `compatible with`, `likely`, `probably` (whole words, case-insensitive).

## What each rule matches

**1. CVE identifier not present in evidence**

```
\bCVE-\d{4}-\d{4,}\b
```

**2. Named exploit or attack tool**

```
\b(metasploit|eternalblue|eternal blue|meterpreter|mimikatz|cobalt strike|nmap|masscan|hydra|medusa|john the ripper|hashcat|sqlmap|burp suite|wireshark|snort|suricata|heartbleed|shellshock|wannacry|notpetya|mirai|zeus|emotet|trickbot|ransomware)\b
```

**3. Specific software version**

```
\bv\d+\.\d+|\bversion\s+\d+|\bopenssl\s+\d|\bapache\s+\d
```

**4. IP address stated — not in evidence**

```
\b(?:\d{1,3}\.){3}\d{1,3}\b
```

**5. Specific patch or version reference**

```
\b(patch\s+(?:MS|KB)\d+|update\s+to\s+version|fixed in\s+version|released in\s+\d{4})\b
```

**6. Named attack technique — not derivable from flow numbers**

```
\b(dns.tunnel(?:ing|ed)?|dns exfiltration|data exfiltration|exfiltrat(?:e|ion|ing)|command.and.control|c2 (?:server|traffic|beacon|channel)|lateral movement|privilege escalation|syn flood|udp flood|icmp flood|http flood|amplification attack|reflection attack|brute.forc(?:e|ing)|credential (?:stuffing|spray)|password spray|dictionary attack|malware|botnet|trojan|backdoor|rootkit|port scan(?:ning)?|network scan(?:ning)?|reconnaissance|host discovery|banner grabbing|zero.day|exploit(?:ing|ation)?|vulnerability)\b
```

**7. Resource exhaustion / DoS impact claim**

```
\b(resource exhaustion|bandwidth exhaustion|connection.pool|thread.pool|memory exhaustion|cpu exhaustion|overwhelm(?:ing|ed)?\s+the\s+(?:server|target|host|network)|flood(?:ing)?\s+the|saturate the bandwidth|denial.of.service|service disruption|downtime)\b
```

**8. Inferred attack outcome**

```
\b(?:could|may|might|will|would)\s+(?:result in|lead to|cause|allow|enable|facilitate)\s+(?:unauthorized|a breach|data exfiltration|lateral movement|privilege escalation|remote (?:access|code execution)|system compromise|downtime)\b
```

**9. Threat-actor framing — not supportable from flow features**

```
\b(an attacker|a malicious actor|threat actor|adversary|the adversary|a malicious user|a bad actor|a threat agent)\b
```

**10. Definitive attacker intent**

```
\b(the attacker (?:intends?|plans?|wants?|aims?|is trying|will)\b)
```

**11. Definitive compromise claim**

```
\b(the (?:server|system|host|machine|network) (?:has been|was|is) (?:compromised|breached|infected|pwned|hacked))\b
```

**12. Hard certainty language**

```
\b(?:definitely|certainly|undoubtedly|absolutely)\s+(?:will|is|has|compromised|infected|indicates)\b
```

**13. [port number not in evidence]**

```
\bport\s+(\d+)\b with the number absent from the evidence
```

**14. [protocol named without its well-known port in evidence]**

```
protocol name (\b(https?|ssh|ftp|smtp|dns|tls|ssl|rdp|smb|imap|pop3|telnet|ldap|snmp|mysql|postgresql|firebird|domain name system)\b) whose well-known port is absent from the evidence, or which has no well-known port
```

**15. Port characterization — labelling a port's purpose is external knowledge**

```
\b(commonly\s+(?:used|associated|utilized)\s+(?:for|with)|conventionally\s+(?:used|utilized|associated)\s+(?:for|with)|primarily\s+associated\s+with|standard\s+port\s+for|typically\s+(?:used|associated)\s+(?:for|with)|well.known\s+port\s+for|is\s+the\s+(?:default|standard|common|well.known)\s+port|designated\s+for|reserved\s+for|used\s+for\s+(?:HTTPS?|SSH|FTP|SMTP|DNS|RDP|SMB|NTP|IMAP|POP3|Telnet)|not\s+typically\s+associated\s+with\s+standard)\b
```

**16. Protocol behavior knowledge — TCP/HTTP session norms are external knowledge**

```
\b(typical(?:ly)?\s+(?:TCP|HTTPS?|web|established|network)\b|normal\s+(?:TCP|HTTPS?|web|network|traffic|behavior|communication)\b|expected\s+(?:TCP|HTTPS?|web|behavior|traffic)\b|(?:for\s+a\s+|in\s+a\s+)(?:typical|normal|properly\s+functioning|standard|established|fully\s+established)\s+(?:TCP|HTTP|HTTPS|web|connection|session|communication)\b|ACK\s+flags?\s+(?:are|is|would\s+be)\s+(?:essential|expected|required|typical|necessary|normal)\b|three.way\s+handshake\b|fully\s+established\s+(?:TCP\s+)?(?:connection|session)\b)
```

**17. Encryption assumption — not in flow evidence**

```
\b(encrypt(?:ed|ion)|unencrypt(?:ed|ion)|secure\s+web\s+traffic|secure\s+(?:communication|connection|channel|session|transfer)\b|SSL[/ ]TLS|plaintext\s+(?:traffic|communication|data)\b)\b
```

**18. External baseline comparison — requires outside knowledge**

```
\b(typical\s+web\s+traffic|standard\s+web\s+(?:traffic|browsing|behavior)\b|normal\s+(?:browsing|web|network)\s+(?:pattern|behavior|activity)\b|deviates?\s+(?:significantly\s+)?from\s+(?:typical|normal|standard|expected)\b|highly\s+anomalous\s+(?:behavior\s+)?for\b|unusual\s+for\s+(?:a\s+)?(?:typical|normal|standard\s+)?(?:TCP|HTTPS?|web|established)\b|not\s+(?:typical|normal|characteristic)\s+(?:of|for)\s+(?:legitimate|normal|standard|typical|regular)\b)
```

**19. Unit assumption — raw flow duration has no guaranteed unit**

```
\b(?:(?:lasted?|persisted?|flow\s+lasted?)\s+for\s+(?:only\s+|approximately\s+|about\s+)?(?:\d+(?:\.\d+)?\s+)?(?:hours?|minutes?|seconds?)\b|(?:lasted?|persisted?|lasted\s+approximately|persisted?\s+for|duration\s+of)\s+(?:approximately\s+)?(?:\d+(?:\.\d+)?\s+)?(?:hours?|minutes?|seconds?)\b|approximately\s+\d+(?:\.\d+)?\s+(?:hours?|minutes?|seconds?)\b|(?:over|about|around|nearly|almost|more\s+than)\s+\d+(?:\.\d+)?\s+(?:hours?|minutes?)\b|lasting\s+(?:only\s+|approximately\s+)?\d+.*?(?:hours?|minutes?|seconds?)\b)
```

**20. [duration stated with an explicit unit]**

```
a duration stated with an explicit unit, (?<![\w.,])(\d{1,3}(?:,\d{3})+|\d+)(?:\.(\d+))?\s*(microsecond|millisecond|second|minute|hour)s?\b, in a sentence for which the rule engine produced no Tier 2 `unit` hit (only when the Tier 2 layer is on)
```

**21. [stated duration contradicts Flow Duration in microseconds]**

```
a stated duration (?<![\w.,])(\d{1,3}(?:,\d{3})+|\d+)(?:\.(\d+))?\s*(microsecond|millisecond|second|minute|hour)s?\b that differs by more than 10% from Flow Duration / 1,000,000 seconds (and is not that value rounded to the stated decimals). A Tier 2 `unit` hit in such a sentence becomes `unit_wrong`.
```

**22. [soft certainty language]**

```
\b(always indicates?|is always|must be|is definitely|will inevitably|cannot be anything other|definitely|certainly|without doubt|absolutely will|guaranteed to)\b
```
